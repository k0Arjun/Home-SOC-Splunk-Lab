# Incident Investigation 03 — Suspicious Script Execution and Process Discovery

## 1. Incident Overview

| Field | Details |
|---|---|
| Incident Name | Suspicious Script Execution and Process Discovery |
| Host | ARJUN-LAB |
| Log Source | Sysmon Operational |
| Event ID | 1 — Process Creation |
| Detection Technologies | Splunk Enterprise, Sysmon |
| Test Framework | Atomic Red Team |
| Severity | Medium / Low (depending on detected behavior) |
| Investigation Status | Completed — Controlled Lab Simulation |

## 2. Alert Description

Suspicious process execution patterns were identified through Sysmon process creation events.

Two behaviors were investigated:

1. A script-host execution chain involving Windows Command Prompt, Windows Script Host and the `whoami.exe` utility.
2. PowerShell execution of the `Get-Process` command to enumerate running processes.

These activities are relevant to understanding how attackers may use built-in Windows utilities and scripting environments during system discovery.

## 3. Evidence Collected

### A. Script Host Identity Discovery

| Attribute | Observation |
|---|---|
| Event ID | Sysmon Event ID 1 |
| Initial Process | cmd.exe |
| Child Process | wscript.exe |
| Final Process | whoami.exe |
| Execution Chain | cmd.exe → wscript.exe → whoami.exe |
| Atomic Technique | T1059.003 test |
| Cleanup | Completed |

The Atomic Red Team test created and executed a VBScript file that invoked `whoami.exe`.

Sysmon captured the process creation events, and the extracted ProcessGuid and ParentProcessGuid fields helped correlate the execution chain.

### B. PowerShell Process Discovery

| Attribute | Observation |
|---|---|
| Event ID | Sysmon Event ID 1 |
| Executable | powershell.exe |
| Command | Get-Process |
| Parent Process | powershell.exe in the observed command execution event |
| MITRE ATT&CK | T1057 — Process Discovery |
| Atomic Test | T1057, Test 3 |
| Cleanup | Completed |

The Atomic Red Team test executed PowerShell's `Get-Process` command to enumerate running processes.

A separate legitimate PowerShell execution of `Get-Process` was also detected during validation.

This demonstrated that the detection can identify both simulated and legitimate process discovery behavior.

## 4. Investigation and Analysis

### A. Script Host Execution

1. Reviewed Sysmon Event ID 1 events.
2. Identified `cmd.exe` launching `wscript.exe`.
3. Identified `wscript.exe` launching `whoami.exe`.
4. Correlated parent and child processes using ProcessGuid and ParentProcessGuid.
5. Confirmed the execution chain was generated by the Atomic Red Team test.
6. Verified that the Atomic test cleanup completed.

### B. Process Discovery

1. Reviewed Sysmon Event ID 1 events.
2. Identified PowerShell execution containing `Get-Process` in its command line.
3. Confirmed the process discovery activity generated by Atomic Red Team.
4. Executed a separate legitimate `Get-Process` command.
5. Confirmed that the same detection also identified the legitimate activity.

The investigation highlighted an important detection-engineering challenge: legitimate administrative behavior can resemble attacker activity.

## 6. Investigation Conclusion

The investigation successfully identified two types of endpoint behavior:

- Script-host execution involving `cmd.exe`, `wscript.exe` and `whoami.exe`.
- PowerShell-based process discovery using `Get-Process`.

The process discovery detection also identified legitimate PowerShell activity, demonstrating the possibility of false positives.

Both activities were generated intentionally in the controlled lab environment using Atomic Red Team or manual validation. There is no evidence from these tests of an actual compromise.

**Final assessment:** Sysmon process creation telemetry and Splunk searches successfully identified the simulated execution chains and process discovery behavior. The investigation also demonstrated why process context and legitimate administrative activity must be considered before classifying an alert as malicious.

## 7. Recommended SOC Analyst Actions

- Examine parent-child process relationships during endpoint investigations.
- Review process command lines, execution paths and user context.
- Investigate unexpected script-host execution, especially when initiated by unusual parent processes.
- Review PowerShell activity and determine whether process enumeration is expected.
- Correlate process creation with network connections, file creation and other endpoint telemetry.
- Tune detections to reduce false positives while preserving visibility into suspicious behavior.

## 8. Lessons Learned

- Sysmon Event ID 1 records process creation.
- ProcessGuid and ParentProcessGuid support process relationship analysis.
- Windows built-in utilities can be used by both administrators and attackers.
- PowerShell Get-Process is a legitimate administrative command that can also appear during attacker reconnaissance.
- Detection results require investigation and context; a matching command line does not automatically mean malicious activity.
